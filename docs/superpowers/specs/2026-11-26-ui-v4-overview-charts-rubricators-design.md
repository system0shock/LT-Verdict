# Дизайн UI v4.4: Обзор, Графики с подсказкой Grafana, Рубрикаторы, Ошибки ПВС, Сравнение и История

Дата: 2026-11-26.

Статус: Approved (утверждено владельцем 2026-11-26).

Связанные решения: [ADR 0035](../../adr/0035-ui-chart-library.md), [ADR 0031](../../adr/0031-error-groups-artifact.md), [ADR 0038](../../adr/0038-transaction-time-series-cache.md).

## 1. Проблема

В `v0.3.0` интерфейс новой оболочки существенно уступал целевому макету:

- Рабочая область не ограничена по ширине, из-за чего графики высотой `78 px` растягиваются на сверхширокие экраны.
- Под каждым графиком рендерится крупный ползунок `<input type="range">`, а наведение показывает только плоскую строку без всплывающей подсказки у курсора и без подсветки точек.
- Карточка вердикта выводит слова `«нарушено»/«в норме»` вместо реальных чисел ресурсных SLA и сырую таблицу `epoch_ms`.
- Карточки инцидентов текстовые, без встроенных графиков; наклоны трендов форматируются в `%/с` (`0 %/с`), а не в `ед./ч`.
- На реальных прогонах с 50–100+ транзакциями и 30–50+ сервисами на плечо плоские списки не масштабируются.
- На «Обзоре» отсутствует выделенная плашка ошибок ПВС из логов (`opensearch_errors` и `error-groups.v1`).
- Экран «Сравнение» ограничивается нагрузкой и не сопоставляет регрессии по аппаратным ресурсам (CPU, память, троттлинг, JVM, пулы, СУБД).

## 2. Целевая архитектура экранов

### 2.1. Единый графический движок (`TimeChart.vue` + `ChartFloatingTooltip.vue`)

- Цветовые токены считываются с ближайшего контейнера `.shell` (а не только с `document.documentElement`).
- Поддерживаются мульти-серии, стеки (`stack`), заливка `areaStyle`, столбцы `BarChart`, зона нарушения порога (`markArea`), коридор подов `min–max`, линия тренда и умная шкала Y (`valueAxis` без принудительного нуля для высокобазовых метрик, например `50–100 %`).
- **Подсказка в стиле Grafana (`ChartFloatingTooltip.vue`)**:
  - 100% непрозрачная высококонтрастная тёмная карточка (`#111822`, `opacity: 1`, чёткая рамка и тень) — линии графика не просвечивают.
  - Позиционируется у указателя мыши через CSSOM `transform: translate3d(...)` с авто-перебросом у краёв экрана (0 нарушений CSP `style-src 'self'`).
  - Подсвечивает активные точки (`circle`) на кривых в выбранном бакете.
  - Поддерживает закрепление кликом (`click-to-pin`), открепление по `Esc` / повторному клику и пошаговый сдвиг `ArrowLeft` / `ArrowRight`.
  - Сохраняет доступность (`aria-label`, клавиатурная навигация, 0 критических/серьёзных нарушений `axe-core`).

### 2.2. Экран «Обзор»

1. **Компактный паспорт вердикта (`VerdictCard.vue`)**: бейдж `PASS`/`FAIL`/`NO_VERDICT`, однострочный паспорт прогона и кликабельные KPI-плитки правил с реальными числовыми значениями (в том числе для ресурсных правил).
2. **Главный двухпанельный график нагрузки и отклика**:
   - Пропорциональная полоса фильтра стадий (`Весь тест` + стадии `stage_binding`).
   - Верхняя панель — `Интенсивность (RPS)` (`Общий RPS` ↔ `По транзакциям`, `Стек RPS` с фоновым слоем остальных транзакций ↔ `Линии`).
   - Нижняя панель на общей оси X — `Отклик (p50 / p95 / p99)`, плюс опциональная дорожка `Ошибки` (столбцы) и пунктир `Baseline`.
   - Компактная строка выбранных транзакций (`≤ 8`) + раскрывающийся табличный рубрикатор транзакций (поиск, фильтр `Все / Отклонения / Выбранные`, сортировка `RPS ↓ / p95 ↓ / Ошибки ↓`, пресеты).
3. **Сетка карточек «Инциденты»** (до 3 колонок) со встроенными мини-графиками проблемных интервалов и переходом в «Глубокий анализ».
4. **Отдельная плашка «Ошибки ПВС из логов и ответы протокола» (`LogErrorsPanel.vue`)**:
   - Видна сразу на «Обзоре» при наличии `opensearch_errors` или `error-groups.v1`.
   - Хронология всплесков ошибок (столбчатый график с подсказкой Grafana), поиск по сервису ПВС / тексту исключения, переключатель `Логи ПВС · OpenSearch` ↔ `Ответы генератора · JTL`, сгруппированная таблица (`сервис`, `тип ошибки / код ответа`, `кол-во и доля`, `окно`, `образец сообщения`, ссылка `Лог ↗` по `source_url` и кнопка перехода к ряду в «Глубоком анализе»).
5. **Вкладочный блок «Проблемные узлы и диагностика»**:
   - `Сервисы × плечи` (`PlatformMap.vue` с фильтром «Только с отклонениями» по умолчанию, поиском и кликабельными ячейками).
   - `Платформа` (топ плиток со спарклайнами).
   - `Тренды` (наклон в `ед./ч` и `п.п./ч` + мини-график с линией тренда).
   - `Ёмкость` (при `analysis_mode === 'capacity_step'`).

### 2.3. Экран «Глубокий анализ»

- Левый sticky фасетный рубрикатор (`320 px`): переключатель доменов `Транзакции` / `Платформа`, группировка `По сервисам` ↔ `По метрикам`, фильтр плеч `A / B / A+B`, поиск, фильтр «Только с отклонениями».
- Два режима рабочей области:
  - **«Свободное сравнение (стопка)»**: до 8 произвольно выбранных дорожек (любые транзакции, сервисы и плечи) на общей временной шкале и с общей подсказкой Grafana (`+ / ✓`, `↑ / ↓`, `×`, пресеты).
  - **«Фокус на одном ряде»**: крупный график активного ряда + полоса статистик окна (`мин / среднее / p50 / p95 / макс`) + сетка остальных рядов набора сравнения.

### 2.4. Экраны «Сравнение» и «История релизов»

- **«Сравнение» (`BaselinePanel.vue`, `BaselineCharts.vue`, `CompareCursorChart.vue`)**:
  - Сводка регрессий по нагрузке/транзакциям и по аппаратным ресурсам (`window_comparison.metrics`).
  - Режимы графиков: `Отклик + Ресурсы вместе`, `Аппаратные ресурсы` (выбор сервиса и плеча с наложением `Текущий` сплошной поверх `Baseline` пунктиром из `getResourceSeriesValues` обоих прогонов), `Нагрузка и транзакции`.
  - Единая фильтруемая таблица регрессий (`Регрессии / Аппаратные ресурсы / Транзакции / Все`) с переходом `На график ↑`.
- **«История релизов» (`HistoryDynamics.vue`, `HistoryPanel.vue`)** и **«Колено ёмкости» (`CapacityKneeChart.vue`)**:
  - Полная ширина рабочей области, токены `.shell`, переключатель метрики в истории (`p95 / RPS / Ошибки`), активные маркеры и непрозрачная подсказка Grafana.
