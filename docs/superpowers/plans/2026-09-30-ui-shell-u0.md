# Каркас нового интерфейса: оболочка за флагом (срез U0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** новая оболочка интерфейса (токены, светлая и тёмная темы, вкладки, шапка с прогоном и вердиктом) включается только параметром `?shell=new`; по умолчанию открывается прежний интерфейс без изменений.

**Architecture:** `App.vue` остаётся владельцем всего состояния. Оболочка добавляет три небольших файла в `ui/src/shell/` (вкладки, обёртка панели, флаг) и один CSS с токенами, действующий только внутри класса `.shell`. Существующие панели (`VerdictCard`, `RunSetup`, `BaselinePanel`, `AdvicePanel`, `AnalysisView` и др.) остаются теми же экземплярами и показываются или скрываются по активной вкладке; в старом режиме условие всегда истинно, поэтому его DOM не меняется.

**Tech Stack:** Vue 3.5, TypeScript, Playwright с `@axe-core/playwright` (уже в `devDependencies`); новых зависимостей нет.

**Spec:** этот файл (раздел «Brainstorming: допущения и вопросы»). Основание: `docs/ui-mockup/implementation-plan.md` (фаза 3, срез U0), макет `docs/ui-mockup/lt-verdict-ui-mockup.html` и снимки `docs/ui-mockup/screens/`, черновики Codex `docs/superpowers/plans/codex-drafts-2026-09-30/` (сверены с кодом, см. ниже), решения владельца от 2026-09-30.

## Brainstorming: допущения и вопросы

Классификация: архитектурный срез небольшого размера (новая подсистема интерфейса, но без контрактов). Интерактивного диалога нет, поэтому решения владельца из задания приняты как исходные, остальное записано допущениями.

- Черновик U0 из `mockup-vs-app-gap.md` называет `WorkspaceNav.vue` и `ui/e2e/workspace-shell.spec.ts`. Берём идею, имена другие (`shell/ShellTabs.vue`, `shell.spec.ts`).
- Утверждение «вердикт первым и sticky-чип уже есть» подтверждено: `VerdictCard.vue`, `verdict-chip` в `App.vue`, `verdict-first.spec.ts`. Не дублируем.
- «Только реальные якоря» из черновика противоречит решению владельца про вкладки-заглушки; берём решение владельца, заглушка только у «Правил».
- Каталога компонентов `LinkedLoadChart`, `OverviewPanel`, `WorkspaceNav` в коде нет, ссылки черновика на них не используются.

Допущения (принимаются по умолчанию, оспариваются в вопросах ниже):

1. Флаг: только точное значение `shell=new` в строке запроса; любое другое значение, регистр и пробелы дают старый интерфейс. Значение читается один раз при загрузке страницы; в новой оболочке есть ссылка «Старый интерфейс» на тот же путь без параметра. В старом интерфейсе ничего не меняется (ни ссылки на новый, ни текстов).
2. Тема: существующий `ref` темы в `App.vue` (начальное значение из `prefers-color-scheme`, переключатель в памяти страницы, без хранения). Токены оболочки переопределяют существующие имена переменных (`--canvas`, `--surface`, `--brand`, ...) только внутри `.shell`, значениями из макета. Встроенные старые панели тем самым получают палитру оболочки без правок их кода. Фон `body` вне `.shell` остаётся прежним.
3. Вкладки порядка из решения владельца. Порядок и составы: Обзор (карточка вердикта, ссылки на скачивание, `AnalyticsPanel`, `GrafanaPanel`), Таблицы (`AnalysisView`, страница buckets), Сравнение (`BaselinePanel`), Правила (заглушка «в разработке»: редактор политики сидит внутри `RunSetup`), ИИ-разбор (`AdvicePanel`), Новый анализ (`RunSetup`, `JenkinsPanel`). Ошибка и статус задачи видны на любой вкладке.
4. Одна панель `role="tabpanel"` с `aria-labelledby` активной вкладки, `aria-controls` всех вкладок указывает на неё. Причина: порядок блоков в `<main>` старого интерфейса нельзя менять (несмежные группы одной вкладки), а обёртка группами дала бы дубли идентификаторов.
5. Панели с одним корневым элементом переключаются `v-show` (сохраняют локальное состояние: подтверждение baseline, согласие ИИ), панели с корнем под `v-if` или несколькими корнями (`AnalysisView`, `JenkinsPanel`, `GrafanaPanel`) переключаются `v-if`.
6. Выбор прогона или сохранённого анализа в боковом списке переводит на вкладку «Обзор», как только загружен результат; иначе выбор ничего не менял бы на экране. Чип шапки на другой вкладке возвращает к карточке вердикта.
7. Боковая панель оболочки: заголовок, вкладки и прежние списки «Accepted runs» и «Saved analyses» (английские, их заменит выбор прогона в U1/U5); в шапке вместо старого блока подписи русские.
8. Шрифты макета не подключаются (внешний хост, приложение локальное): остаётся системный шрифт. Радиусы и отступы макета переносятся только там, где это дёшево (панели, вкладки).
9. Язык страницы `<html lang="en">` не меняется; русские элементы оболочки помечаются `lang="ru"`.

Вопросы владельцу (не блокируют срез):

1. Порядок вкладок: оставить порядок из задания или, как в макете, вынести «Новый анализ» первой кнопкой сверху?
2. Список прогонов в боковой панели оболочки остаётся английским до U1/U5. Устраивает, или перевести три-четыре заголовка уже сейчас (правка семи строк в шаблоне `App.vue`)?
3. Нужно ли адресуемое состояние вкладки (`?shell=new&tab=tables`) для ссылок и e2e? Сейчас нет: router и URL-состояние вне U0.
4. Переключение на «Обзор» при загрузке результата (допущение 6) приемлемо, или предпочтительнее оставаться на текущей вкладке?

```ts
import { nextTick } from 'vue'
import { SHELL_LABELS, SHELL_TABS, type ShellTabKey } from './labels'
import { SHELL_PANEL_ID, shellTabId } from './shell'

const model = defineModel<ShellTabKey>({ required: true })

async function moveTo(index: number) {
  const count = SHELL_TABS.length
  const tab = SHELL_TABS[((index % count) + count) % count]
  model.value = tab.key
  await nextTick()
  document.getElementById(shellTabId(tab.key))?.focus()
}

function onKeydown(event: KeyboardEvent, index: number) {
  const next: Record<string, number> = { ArrowDown: index + 1, ArrowRight: index + 1, ArrowUp: index - 1, ArrowLeft: index - 1, Home: 0, End: SHELL_TABS.length - 1 }
  if (!(event.key in next)) return
  event.preventDefault()
  void moveTo(next[event.key])
}
```
