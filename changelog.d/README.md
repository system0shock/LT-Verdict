# Фрагменты журнала изменений

Журнал изменений LT Verdict собирается из фрагментов. Один срез или PR
добавляет один файл в этот каталог и не трогает `CHANGELOG.md`, поэтому
параллельные PR больше не конфликтуют в журнале.

## Правила

- Имя файла: `<номер-или-slug>.<тип>.md`.
  - `<номер-или-slug>`: номер PR или короткий slug среза из латинских букв,
    цифр, `-` и `_`, без точек: `86`, `u5a-compare-tab`, `adr0018-s1a`.
  - `<тип>`: `added` (новая возможность), `changed` (изменение поведения или
    видимого текста), `fixed` (исправление ошибки). Допускается регистр
    `Added`, `Changed`, `Fixed`, в репозитории принят нижний.
- Один срез, один файл. Если нужны записи разных типов, их несколько:
  `86.added.md` и `86.fixed.md`.
- Содержимое: UTF-8, русский язык, записи в том же виде, как в
  `CHANGELOG.md`: маркер списка `-` с пробелом, продолжение строки с отступом в два
  пробела. Одна запись описывает, что изменилось для пользователя, чего не
  менялось (API, схемы, ядро, если это важно), и известные ограничения.
- В файле нет заголовков (строк с `#`): раздел определяет тип в имени файла.
- Служебные файлы каталога (`README.md` и файлы с именем, начинающимся с
  точки) фрагментами не считаются. Любой другой файл с неверным именем
  отклоняет `--check`.

## Пример

Файл `changelog.d/86.changed.md`:

```markdown
- Вкладка «Сравнение» новой оболочки (срез U5a) по-русски: панель baseline с
  явным подтверждением условий пары и предупреждениями в порядке сервера.
  Прежний интерфейс остаётся английским, API и серверные контракты не
  менялись.
```

## Проверка и сборка

```text
python tools/changelog_assemble.py            # предпросмотр собранного текста
python tools/changelog_assemble.py --check    # проверка фрагментов (CI)
python tools/changelog_assemble.py --apply    # только при релизе
```

- Фрагменты сортируются по номеру и slug (естественный порядок: `87` перед
  `100`), внутри раздела `Added`, `Changed`, `Fixed`. Записи добавляются в
  конец соответствующего подраздела `### Added`, `### Changed`, `### Fixed`
  секции `## [Unreleased]`.
- `--apply` запускает человек при выпуске версии: скрипт вставляет записи в
  `CHANGELOG.md` и удаляет вставленные фрагменты. После этого секция
  `Unreleased` получает номер версии и дату, сверху создаётся пустая секция
  `Unreleased` (см. `docs/development-process.md`). Прямые правки
  `CHANGELOG.md` допустимы только при релизе.
- PR, меняющий `src/main`, `ui/src`, `docs/contracts` или `tools`, обязан
  добавить фрагмент либо написать в теле PR отдельной строкой
  `Documentation impact: none` (проверка `Changelog`).
