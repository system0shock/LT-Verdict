# Автошаг выборки источника (ADR 0014, часть 4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** онлайн-сбор рядов ресурсов сам подбирает шаг сетки, только когда заявленный шаг не укладывается в `C_max` = 1 500 000 ячеек, и при этом никогда не скрывает нарушение порога: огрубление допускается только для рядов с подходящей агрегацией, остальные случаи отказывают до сети или публикуют предупреждение `RESOLUTION_REDUCED`.

**Architecture:** расчёт шага живёт в слое `sources` (новый файл `AutoStep.kt` рядом с `deriveAutoWindow`), потому что ему нужны профили источника (число запросов, правила, агрегации, интервал опроса) и вывод окна; ядро (`core`) получает только два новых значения `aggregation`. Шаг выбирается один раз на весь выбор профилей в `resolveWindow` до первого сетевого запроса и передаётся в `SourceRequest.stepMillis`; существующая проверка по фактическим ячейкам остаётся последним барьером. Агрегацию не выбирает ни планировщик, ни ядро: её объявляет автор профиля вместе с выражением запроса, снимок только несёт и хэширует метку, а планировщик до сети проверяет совместимость метки с оператором правила.

**Tech Stack:** Kotlin 2 (JVM 21), JUnit 5, JSON Schema + Ajv (`ui/scripts/verify-policy-schema.mjs`), Vue 3 + Playwright (только срез S5). Новых зависимостей нет.

**Spec:** `docs/adr/0014-resource-series-limits-autostep-arm-api.md` (часть 4, «Потеря всплесков при автошаге», «Решения владельца (2026-09-30)», «Открытые вопросы», пункт 2 раздела «Следствия»); решения владельца 2026-10-02: исключение для неотрицательных событийных приращений (принято вместе с `docs/adr/0018-policy-platform-rules-small-samples.md`, вопрос 12, ветка `docs/adr-0018-policy-platform-rules`, в `origin/main` ещё не влит). Замер: `docs/ui-mockup/adr-a-measurement-2026-09-30.md` в основном чекауте (untracked, в репозиторий не входит). Формат плана: `docs/superpowers/plans/2026-09-30-snapshot-limits-d1.md`.

## Принятые решения плана

1. **Где живёт расчёт.** Чистые функции в `io.ltverdict.sources.AutoStep.kt`; вызов из `resolveWindow` (`SourceAnalysis.kt`). Ядро не меняется, кроме enum (S1). Адаптер источника (`PromqlSource.acquire`) шаг не выбирает: получает уже готовый `SourceRequest`, поэтому одиночный и множественный сбор ведут себя одинаково.
2. **Откуда `s_min`.** Из профиля: поле `scrape_interval_ms` в новой `source-connections.v3` (целые секунды 1-3 600). Не из запроса пользователя (пользователь задаёт заявленный шаг, а не интервал опроса) и не из ответа Prometheus (нужен до `query_range`; для `grafana_proxy`, VictoriaMetrics и InfluxDB нет единого способа). Для нескольких профилей берётся максимум по профилям, у которых есть запросы. Нет поля - отказ `AUTO_STEP_SCRAPE_INTERVAL_REQUIRED`, но только в режиме `step_mode: auto`; в режиме `fixed` и в v1-v3 ничего не проверяется.
3. **Форма запроса.** `source-request.v4`: как v3 плюс обязательное `window.step_mode` (`fixed` | `auto`). `step_ms` - заявленный шаг. Режим `fixed` равен v3 (включая кратность `margin_ms` и `max_idle_gap_ms`), режим `auto` отменяет кратность и требует `max_idle_gap_ms >= step_ms`; заявленный шаг в явном окне по-прежнему обязан делить окно.
4. **Алгоритм.** Кандидаты - целые секунды от заявленного шага до `min(60 с, max_idle_gap_ms)` для авто-окна и до 60 с для явного; первый, для которого `S x N(s) <= C_max`. Для авто-окна `N(s)` считает `deriveAutoWindow` для каждого кандидата; `AUTO_WINDOW_SPAN_UNSUPPORTED` означает "кандидат не подходит", остальные отказы вывода окна пробрасываются как есть. Для явного окна подходят только делители. Нет кандидата - `AUTO_STEP_UNSATISFIABLE` с наибольшим допустимым `S`.
5. **Агрегация по типу правила.** Автор профиля объявляет `aggregation`; планировщик только проверяет совместимость и только когда шаг действительно огрубляется: `gt` требует `interval_max`, `lt` требует `interval_min`, иначе `AUTO_STEP_AGGREGATION_MISMATCH`. Правила действуют одинаково для `effect = sla` и `diagnostic`. Ряд с двумя правилами `gt` и `lt` не проходит. Исключение (S4): ряд с `non_negative_events: true` и правило `gt` с порогом не выше 0 допускают `interval_mean`, `interval_rate`, `interval_max`, но не `interval_min` (это сочетание отвергается при разборе профиля при любом шаге, ADR 0018) и допускают правило `min_consecutive_cells = 1` в ячейках.
6. **Связь со снимком.** Снимок несёт метку агрегации ряда (она входит в `semanticSha256` только у файлов с новыми значениями), правила в снимке всегда выражены в ячейках (для правил по длительности ядро получает `ceil(span / step)`), шаг и число точек - в сетке снимка. Публикация выбора шага (`step_origin`, `requested_step_ms`, `series_count`, `cell_budget`, `cells_per_series`, `warnings`) идёт в `source_summary` через уже существующий механизм `windowProvenance` (`PromqlSource.kt:471-472`), поэтому попадает в `source_acquisition_sha256`.
7. **Правила в ячейках при огрублении.** Любое правило, объявленное в ячейках (`min_consecutive_cells`), отказывает (`AUTO_STEP_RULE_IN_CELLS`), как требует ADR 0014 часть 4; длительность задаётся `min_consecutive_span_ms` (S3), а правило "хотя бы один интервал" записывается длительностью не больше шага. Единственное исключение - правило `min_consecutive_cells = 1` для событийного ряда с исключением (S4): так записан профиль OOM и рестартов в ADR 0018 (D10), а решение владельца 2026-10-02 снимает с них правило автошага. Допуск `min_consecutive_cells = 1` для остальных рядов не принят (решение владельца 2026-10-04, п. 3): отказ.
8. **Что значит `RESOLUTION_REDUCED`.** Публикуется только при фактическом огрублении (применённый шаг больше заявленного) и перечисляет ряды, у которых нет правила с подходящим пиковым агрегатом: ряды без правил и событийные ряды с `interval_mean`/`interval_rate`.

## Review Focus

Входы и условия, которые спецификация подразумевает, но тесты базовых сценариев не покрывают. Каждая строка получает тест в задаче-владельце.

1. Запрос с жёстким окном и скобками внутри строки: `rate(x[1m]) + avg_over_time(y[$__interval])` при огрублении обязан отказать, а `x{pod=~"a[0-9]"}[$__interval]` не должен ложно отказывать (S2, задача 4).

private fun parseWindowV4(element: JsonElement): RequestWindow {
    val value = element.sourceObject()
    return when (value.sourceString("origin")) {
        "explicit" -> {
            value.rejectUnknown(setOf("origin", "start_epoch_ms", "end_epoch_ms", "step_ms", "step_mode"))
            // Заявленный шаг явного окна делит окно нацело и в режиме auto: иначе "шаг по умолчанию" вынужденно менялся бы.
            // Число точек при заявленном шаге в режиме auto не ограничивается: подходящий шаг найдёт планировщик (explicitGridCells).
            val stepAuto = parseStepMode(value)
            parseExplicitWindow(value, strictStep = true, checkCells = !stepAuto).copy(stepAuto = stepAuto)
        }
        "auto" -> {
            value.rejectUnknown(setOf("origin", "step_ms", "step_mode", "margin_ms", "max_idle_gap_ms"))
            val step = value.sourceLong("step_ms", ::requestInvalid)
            validateStepMillis(step, strict = true)
            val stepAuto = parseStepMode(value)
            val margin = value.sourceLong("margin_ms", ::requestInvalid)
            val maxIdleGap = value.sourceLong("max_idle_gap_ms", ::requestInvalid)
            if (margin !in 0..MAX_MARGIN_MILLIS || maxIdleGap < step) requestInvalid()
            // Режим fixed равен v3: запас и допуск простоя кратны шагу. Режим auto шага заранее не знает, кратность отменяется.
            if (!stepAuto && (margin % step != 0L || maxIdleGap % step != 0L)) requestInvalid()
            AutoWindow(margin, maxIdleGap, step, stepAuto)
        }
        else -> requestInvalid()
    }
}

private fun parseStepMode(value: JsonObject): Boolean =
    when (value.sourceString("step_mode")) {
        "fixed" -> false
        "auto" -> true
        else -> requestInvalid()
    }

import io.ltverdict.core.MAX_POINTS_PER_SERIES
import io.ltverdict.core.MAX_RESOURCE_SERIES
import io.ltverdict.core.RunPeriodV1

internal const val AUTO_STEP_UNSATISFIABLE = "AUTO_STEP_UNSATISFIABLE"
internal const val AUTO_STEP_SCRAPE_INTERVAL_REQUIRED = "AUTO_STEP_SCRAPE_INTERVAL_REQUIRED"
internal const val AUTO_STEP_BELOW_SCRAPE_INTERVAL = "AUTO_STEP_BELOW_SCRAPE_INTERVAL"
internal const val AUTO_STEP_QUERY_NOT_INTERVAL_BOUND = "AUTO_STEP_QUERY_NOT_INTERVAL_BOUND"
internal const val AUTO_STEP_AGGREGATION_MISMATCH = "AUTO_STEP_AGGREGATION_MISMATCH"
internal const val RESOLUTION_REDUCED = "RESOLUTION_REDUCED"

// Потолок шага снимка: целые секунды 1..60 (ResourceSnapshot.kt, INVALID_GRID).
internal const val MAX_STEP_MILLIS = 60_000L

/** Отказ планировщика до сети: код для UI и CLI плюс текст с подробностью, например наибольшим допустимым числом рядов. */
internal class SourcePlanRefusal(
    val code: String,
    val text: String,
) : IllegalArgumentException(code)

internal data class StepChoice(
    val stepMillis: Long,
    val cellsPerSeries: Long,
)

/**
 * Наименьший целый шаг в секундах из [requestedMillis, ceilingMillis], при котором seriesCount x ячеек <= cellBudget.
 * [gridCells] возвращает число ячеек сетки при шаге либо null, если шаг неприменим к окну.
 */
internal fun planStep(
    seriesCount: Int,
    cellBudget: Long,
    requestedMillis: Long,
    ceilingMillis: Long,
    gridCells: (Long) -> Long?,
): StepChoice {
    var fewestCells: Long? = null
    var step = requestedMillis
    while (step <= ceilingMillis) {
        val cells = gridCells(step)
        if (cells != null) {
            if (seriesCount.toLong() * cells <= cellBudget) return StepChoice(step, cells)
            fewestCells = minOf(fewestCells ?: cells, cells)
        }
        step += 1_000L
    }
    val detail =
        fewestCells?.let { "the largest supported series count for this period is ${minOf(cellBudget / it, MAX_RESOURCE_SERIES.toLong())}" }
            ?: "no step in the allowed range fits this window"
    throw SourcePlanRefusal(
        AUTO_STEP_UNSATISFIABLE,
        "No step from ${requestedMillis / 1_000} s to ${ceilingMillis / 1_000} s keeps $seriesCount series within $cellBudget cells; $detail",
    )
}

/** Явное окно: подходят только шаги, которые делят окно нацело. */
internal fun explicitGridCells(
    startMillis: Long,
    endMillis: Long,
): (Long) -> Long? =
    { step ->
        val span = endMillis - startMillis
        if (span % step == 0L && span / step in 1..MAX_POINTS_PER_SERIES.toLong()) span / step else null
    }

/** Авто-окно: число ячеек выводит тот же deriveAutoWindow, что и сбор; "слишком много ячеек" - кандидат не подходит. */
internal fun autoGridCells(
    period: RunPeriodV1,
    auto: AutoWindow,
): (Long) -> Long? =
    { step ->
        when (val outcome = deriveAutoWindow(period, auto.copy(stepMillis = step))) {
            is AutoWindowOutcome.Derived -> (outcome.window.endMillis - outcome.window.startMillis) / step
            is AutoWindowOutcome.Refused ->
                if (outcome.reasonCode == AUTO_WINDOW_SPAN_UNSUPPORTED) null else throw IllegalArgumentException(outcome.reasonCode)
        }
    }

internal data class AppliedStep(
    val requestedMillis: Long,
    val stepMillis: Long,
    val cellsPerSeries: Long,
    val seriesCount: Int,
    val cellBudget: Long,
    val reduced: List<ReducedSeries>,

/** Шаг для режима step_mode = auto: отказы до сети, затем перебор, затем проверки профилей при фактическом огрублении. */
internal fun applyAutoStep(
    selected: List<SourceProfile>,
    requestedMillis: Long,
    ceilingMillis: Long,
    cellBudget: Long,
    gridCells: (Long) -> Long?,
): AppliedStep {
    val seriesCount = selected.sumOf { it.queries.size }
    // Нет рядов - нет снимка и нечего бюджетировать: шаг остаётся заявленным.
    if (seriesCount == 0) return AppliedStep(requestedMillis, requestedMillis, gridCells(requestedMillis) ?: 0L, 0, cellBudget, emptyList())
    val withQueries = selected.filter { it.queries.isNotEmpty() }
    withQueries.firstOrNull { it.scrapeIntervalMillis == null }?.let {
        throw SourcePlanRefusal(
            AUTO_STEP_SCRAPE_INTERVAL_REQUIRED,
            "Profile ${it.id} does not declare scrape_interval_ms (source-connections.v3); declare it or use step_mode fixed",
        )
    }
    val floor = withQueries.maxOf { checkNotNull(it.scrapeIntervalMillis) }
    if (requestedMillis < floor) {
        throw SourcePlanRefusal(
            AUTO_STEP_BELOW_SCRAPE_INTERVAL,
            "Requested step $requestedMillis ms is below the scrape interval $floor ms; raise the step or use step_mode fixed",
        )
    }
    val choice = planStep(seriesCount, cellBudget, requestedMillis, ceilingMillis, gridCells)
    val reduced = if (choice.stepMillis > requestedMillis) checkCoarsening(selected) else emptyList()
    return AppliedStep(requestedMillis, choice.stepMillis, choice.cellsPerSeries, seriesCount, cellBudget, reduced)
}

private fun checkCoarsening(selected: List<SourceProfile>): List<ReducedSeries> {

            reduced += ReducedSeries(if (qualify) qualifiedSeriesId(profile.id, query.id) else query.id, query.aggregation)

private val QUOTED_LITERAL = Regex("""\"(?:\\.|[^\"\\])*\"|'(?:\\.|[^'\\])*'|`[^`]*`""")
private val RANGE_SELECTOR = Regex("""\[([^\]]*)]""")

/** Каждый range-селектор выражения - ровно [$__interval]; строковые литералы (label-regex) не считаются. */
internal fun usesOnlyIntervalRanges(expression: String): Boolean {
    val ranges = RANGE_SELECTOR.findAll(QUOTED_LITERAL.replace(expression, "\"\"")).map { it.groupValues[1].trim() }.toList()
    return ranges.isNotEmpty() && ranges.all { it == "\$__interval" }
}

private val INFLUX_SELECT_KEYWORD = Regex("""(?i)\bSELECT\b""")
private val INFLUX_TIME_GROUPING = Regex("""(?i)\btime\s*\(\s*([^,)\s]*)""")

/** InfluxQL: один SELECT без подзапросов и каждая группировка GROUP BY time(...) - ровно $__interval. */
internal fun usesOnlyIntervalGrouping(expression: String): Boolean {
    val bare = QUOTED_LITERAL.replace(expression, "\"\"")
    val groupings = INFLUX_TIME_GROUPING.findAll(bare).map { it.groupValues[1] }.toList()
    return INFLUX_SELECT_KEYWORD.findAll(bare).count() == 1 && groupings.isNotEmpty() && groupings.all { it == "\$__interval" }
}

private fun resolveWindow(
    service: AnalysisService,
    request: AnalysisRequest,
    windowed: WindowedSourceRequest,
    profiles: List<SourceProfile>,
    cellBudget: Long,
    checkCancelled: () -> Unit,
): SourceRequest {
    val profileId = windowed.profileIds.first()
    val additional = windowed.profileIds.drop(1)
    // Provenance окна публикуют v3 и v4: байты v1 и v2 остаются неизменными. Поля шага - только v4.
    val publishesWindow = windowed.schemaVersion == "source-request.v3" || windowed.schemaVersion == "source-request.v4"
    val publishesStep = windowed.schemaVersion == "source-request.v4"

    fun selected(): List<SourceProfile> =
        windowed.profileIds.map { id -> profiles.singleOrNull { it.id == id } ?: throw IllegalArgumentException("SOURCE_PROFILE_NOT_FOUND") }
    return when (val window = windowed.window) {
        is ExplicitWindow -> {
            val applied =
                if (window.stepAuto) {
                    applyAutoStep(selected(), window.stepMillis, MAX_STEP_MILLIS, cellBudget, explicitGridCells(window.startMillis, window.endMillis))
                } else {
                    null
                }
            SourceRequest(
                profileId,
                window.startMillis,
                window.endMillis,
                applied?.stepMillis ?: window.stepMillis,
                additional,
                if (publishesWindow) {
                    buildJsonObject {
                        put("window_origin", "explicit")
                        if (publishesStep) putStepProvenance(applied)
                    }
                } else {
                    null
                },
            )
        }
        is AutoWindow -> {
            val period = runPeriodFromJson(recognizedPeriod(service, request, window, checkCancelled))
            val applied =
                if (window.stepAuto) {
                    applyAutoStep(
                        selected(),
                        window.stepMillis,
                        minOf(MAX_STEP_MILLIS, window.maxIdleGapMillis),
                        cellBudget,
                        autoGridCells(period, window),
                    )
                } else {
                    null
                }
            val effective = if (applied == null) window else window.copy(stepMillis = applied.stepMillis)
            val derived =
                when (val outcome = deriveAutoWindow(period, effective)) {
                    is AutoWindowOutcome.Derived -> outcome.window
                    // Отказ авто-окна возвращается до внешней выборки: границы теста не угадываются.
                    is AutoWindowOutcome.Refused -> throw IllegalArgumentException(outcome.reasonCode)

                derived.startMillis,
                derived.endMillis,
                derived.stepMillis,
                additional,
                provenance,
                autoDerivedWindow = true,
