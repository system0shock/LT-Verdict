# ADR 0035: Библиотека графиков UI (Apache ECharts)

Дата: 2026-11-19.

Статус: Proposed (в Accepted переводится только по слову владельца). Номер 0035 выбран как
следующий после 0034; перед слиянием его нужно перепроверить по `origin/main`.

## Контекст

Новая оболочка UI (`?shell=new`) рисует все ряды собственными компонентами на SVG
(`SharedCursorChart.vue`, `DeepCursorChart.vue`, `LoadCharts.vue`): полоса высотой около 70 px
без оси значений, сетки, делений времени и стадий теста; курсор двигается ползунком под блоком.
Сверка с макетом интерфейса 2026-11-19 показала, что ни один график не достигает уровня макета:
нет большого графика метрики, наложения рядов со стадиями, графика сравнения с прошлым релизом,
спарклайнов в плитках и карточках.

Решения владельца 2026-11-19:

1. Графики строятся на готовой библиотеке, а не на собственной отрисовке.
2. Библиотека должна годиться и для рендера в отчёты и иметь широкий набор возможностей
   (спарклайны и другие виды графиков).
3. Новые графики появляются только в новой оболочке; старый интерфейс не меняется.

Ограничения:

1. `Content-Security-Policy` локального сервера: `script-src 'self'`. Библиотека поставляется
   только внутри бандла UI, без CDN.
2. Отчёты (HTML, AsciiDoc, Confluence-ready XHTML, SVG) строит ядро на JVM
   (`HtmlReport.kt`, `StaticLoadChart.kt`). JavaScript-движка в процессе нет.
3. Confluence и AsciiDoc не исполняют скрипты: для них пригоден только статический SVG.
4. Вердикт, `analysis-result.json`, identity и схемы от способа рисования не зависят.

## Решение

### D1. Библиотека: Apache ECharts

В `ui/package.json` добавляется production-зависимость `echarts` (лицензия Apache-2.0) с точной
версией, как у `vue`. Обёртка `vue-echarts` не добавляется: один собственный компонент-обёртка
в `ui/src/shell/`.

Почему ECharts, а не uPlot или Chart.js:

| Требование | ECharts | uPlot | Chart.js |
| --- | --- | --- | --- |
| Рендер в SVG | да, SVG-рендерер и рендер в строку без DOM | нет, только canvas | нет, только canvas |
| Порог с подписью, заливка зоны, полосы стадий | `markLine`, `markArea` | плагины вручную | отдельный плагин |
| Общий курсор нескольких графиков | `connect` | sync-плагин | нет |
| Тепловая карта, полоса min–max, спарклайны | да | частично | плагины |
| Размер | большой, подключается по модулям | малый | средний |

uPlot быстрее и легче, но без SVG не выполняет требование про отчёты.

### D2. Подключение по модулям

Импортируются только нужные типы графиков и компонентов (`echarts/core`, линии, столбцы,
тепловая карта, оси, сетка, подсказка, `markLine`, `markArea`, `dataZoom`) и SVG-рендерер.
Размер бандла до и после записывается в PR первого среза.

### D3. Рендерер по умолчанию: SVG

Графики UI рисуются SVG-рендерером: один и тот же результат годится для экрана, печати и
экспорта, а проверки доступности и Playwright-тесты продолжают работать с DOM, а не с пикселями
canvas. Переход на canvas для отдельных графиков допускается, если измерение покажет, что SVG не
справляется с числом точек; лимит точек на ряд задаёт существующий автошаг (ADR 0014).

### D4. Отчёты ядра в этом ADR не меняются

Отчёты ядра продолжают использовать статический SVG из Kotlin. Перевод отчётов на ECharts это
отдельное решение со своим ADR; варианты для него:

1. HTML-отчёт несёт встроенный скрипт ECharts и данные; статические форматы (AsciiDoc,
   Confluence, SVG) остаются на SVG из Kotlin. Цена: самодостаточный `report.html` вырастает на
   сотни килобайт.
2. Экспорт из UI: браузер рендерит те же графики в строку SVG и передаёт её в отчёт. Цена: отчёт,
   собранный из CLI без браузера, остаётся с графиками Kotlin, два вида отчётов расходятся.
3. JS-движок внутри JVM для серверного рендера. Цена: тяжёлая production-зависимость ядра.

До этого решения отчёты из CLI и из UI выглядят по-прежнему.

### D5. Старые компоненты

`SharedCursorChart.vue`, `DeepCursorChart.vue` и графики новой оболочки заменяются по срезам;
`LoadCharts.vue` и `BaselineCharts.vue` старого интерфейса не трогаются.

## Последствия

- Новая production-зависимость UI; `gradle.lockfile` и зависимости ядра не меняются.
- Растёт бандл UI; величина измеряется в первом срезе.
- Клавиатурное управление курсором и текстовые альтернативы графиков, которые есть сейчас,
  должны сохраниться: это критерий приёмки первого среза, а не свойство библиотеки.
- Офлайн-сборка: пакет должен попасть в `package-lock.json` и офлайн-кэш сборки.

## Не входит

Перевод отчётов ядра, новые ряды в API, изменения ядра и контрактов, старый интерфейс.
