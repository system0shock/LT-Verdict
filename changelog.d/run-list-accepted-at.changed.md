- Список прогонов различим и упорядочен по свежести: `source.json` получает
  необязательное поле `accepted_at` (момент приёма входа, UTC, миллисекунды), его
  возвращают `GET /api/runs`, `POST /api/inputs` и объект `run` ответа Jenkins
  (`null` для прогонов, сохранённых раньше). `GET /api/runs` сортирует по
  `accepted_at` по убыванию, затем по `run_id`; прогоны без поля идут после
  новых; неизвестный `after` даёт 400. В списке интерфейса рядом с «тип · sha8»
  показано время приёма. Повторная загрузка тех же байт сохраняет первое время;
  `run_id`, `analysis_id` и результаты анализа не менялись, старые каталоги
  данных остаются валидными. Метка прогона и номер сборки Jenkins не вводились.
