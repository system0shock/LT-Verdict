# Capacity Explicit Stages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Добавить optional `capacity-plan.v1` с явными stage трёх осей, консервативными bounds/evidence и неизменным standard flow.

**Architecture:** `CapacityPlan.kt` строго валидирует input и bindings, `CapacityAnalysis.kt` чисто вычисляет 10s facts/bounds из существующих metrics/resource/window-policy facts. Затем одна последовательная интеграция использует текущие `AnalysisService`, immutable RunBundle, CLI/API и Vue. Никаких нового engine/runtime/service/registry, inference/knee или stats refactor.

**Tech Stack:** Kotlin/JDK + existing kotlinx.serialization/metrics/storage/Ktor; Vue 3/TypeScript/Playwright; no dependencies.

**Spec:** `docs/superpowers/specs/2026-09-06-capacity-design.md`

## Global constraints

- Standard without plan preserves current identity/result bytes, artifacts and verdict.
- One `rps|concurrency|users` axis, at most 64 explicit unique non-overlapping `[from,to)` stages; no old RPS-only or inferred-stage proposal.
- Plan binds load SHA-256 and resource semantic SHA-256. Neither `resource-snapshot.v1` nor `policy.v1` changes.
- Stage evaluation window is an existing snapshot window wholly inside its stage; capacity accepts only 1/2/5/10s snapshot step, 10s UTC-aligned evaluation, and at least 30 complete bins/300s.
- Achieved is type-7 `p05_10s`, with min/max/coverage/bin count. Bound load is `min(target,achieved)`, never target alone.
- RPS uses actual request starts. Concurrency/users require `achieved_series_id`, `unit=count`, `aggregation=interval_mean`, nonnegative values; its role is not restricted. Rebin only complete source cells, time-weighted.
- Guard IDs select existing `effect=diagnostic` rules on generator-role series; guards are not product SLA. Existing business policy and resource `effect=sla` rules apply to the evaluation window.
- Missing guard/bin/telemetry, target miss, gaps, invalid bindings, non-monotonic targets/outcomes or verified-load order => `INDETERMINATE`; generator failure above valid PASS creates no upper bound.
- Missing required capacity => `NO_POLICY`; no SLA => `NO_POLICY/CAPACITY_SLA_MISSING`; lower >= required => PASS, upper <= required => FAIL, otherwise NO_VERDICT.
- `capacity_knee=null`, reason `KNEE_DETECTOR_NOT_IMPLEMENTED`; no HIGH confidence/extrapolation/saturation causal claim or stage-specific OpenSearch/PG assertion.
- No production dependency, resource/policy/statistics refactor or statistical oracle/corpus change. Before shared integration preserve the statistical source manifest; rerun it after integration with a distinct manifest.

**Interfaces:**

```kotlin
internal sealed interface CapacityPlanValidation {
    class Valid internal constructor(
        internal val plan: CapacityPlanV1, val semanticSha256: String, rawBytes: ByteArray,
    ) : CapacityPlanValidation { fun rawBytes(): ByteArray }
    data class Invalid(val errors: List<PolicyValidationError>) : CapacityPlanValidation
}
internal enum class CapacityLoadAxis(val wireName: String, val unit: String) {
    RPS("rps", "requests/s"), CONCURRENCY("concurrency", "count"), USERS("users", "count")
}
internal data class CapacityPlanV1(
    val loadInputSha256: String, val resourceSnapshotSha256: String,
    val loadAxis: CapacityLoadAxis, val achievedSeriesId: String?,
    val targetToleranceRatio: BigDecimal, val requiredCapacity: BigDecimal?,
    val generatorGuardRuleIds: List<String>, val stages: List<CapacityStageV1>,
)
internal data class CapacityStageV1(
    val id: String, val target: BigDecimal, val fromEpochMillis: Long,
    val toEpochMillis: Long, val evaluationWindowId: String,
)
internal fun validateCapacityPlan(source: InputStream, maxBytes: Int = MAX_CAPACITY_PLAN_BYTES): CapacityPlanValidation
internal fun validateCapacityBinding(plan: CapacityPlanValidation.Valid, inputSha256: String, resources: ResourceValidation.Valid): List<PolicyValidationError>
```

Wire form is closed: root has `schema_version:"capacity-plan.v1"`, `load_input_sha256`, `resource_snapshot_sha256`, `load_axis`, `achieved_load`, `generator_guard_rule_ids`, `stages`; achieved load has fixed `statistic:"p05_10s"`, `target_tolerance_ratio`, optional positive `required_capacity`, and required `achieved_series_id` only for concurrency/users. Stage has `id,target,from_epoch_ms,to_epoch_ms,evaluation_window_id`.

Use 1..64 stages and 0..256 unique guard IDs (empty means missing health basis,
not healthy; evaluator will abstain). IDs use existing resource identifier
syntax; numbers use magnitude <=1e18,32 significant/12 fractional digits,
64-byte token/absolute exponent64. Epoch timestamps use existing ingest bound.
Preserve declared stage order in semantic hash: evaluator, not sorter, detects
non-monotonic targets. Guard IDs are a semantic set and canonicalized sorted
only when hashing; typed plan keeps input order for accurate validation pointers.
Duplicate IDs rejected. Binding rejects bad hashes/references/units/negative
achieved observations and incompatible grid. Fewer than30 bins is a stage
insufficiency to report, not a JSON syntax error. Null observations remain gaps.
