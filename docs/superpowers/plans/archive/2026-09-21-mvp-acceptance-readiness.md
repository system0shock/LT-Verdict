# Подготовка MVP к приёмке — краткий план

Дата: 2026-09-21. План работ, не команда на запуск приёмки.

**Цель:** закончить предусмотренные MVP функции и локальные проверки, чтобы отдельная сквозная приёмка проверяла готовый продукт.
**Основа:** docs/development-plan-v0.6.md; актуальные поправки — docs/mvp-three-tracks-checkpoint-2026-09-06.md и docs/session-handoff.md.
**Подход:** существующие Kotlin/API/Vue компоненты, минимальные изменения; независимые задачи распределять между агентами. Общие API/UI файлы имеют одного владельца. Перед каждым блоком уточнять небольшой implementation plan и его проверки.

- [x] 1. Сверить backlog с кодом: убрать устаревшие OPEN для baseline/selector, составить единый список готово/доделать/проверить на приёмке. Не переоткрывать принятые ограничения корреляций.
- [x] 2. Довести AI до пользовательской функции: production runner, настройка ModelStudio, запуск/статус/API/UI, сохранение advice, таймаут/отмена/отказ без изменения SLA. Исправить известные локальные дефекты, включая ограничение чтения advice manifest. Использовать найденные ошибки как regression cases; уточнить prompt и отображение фактов/гипотез. Изменения промпта не считать доказанным улучшением качества без новой оценки; новые внешние вызовы не запускать в рамках подготовки.
- [x] 3. Закончить аналитический интерфейс: N-run dynamics, transaction/baseline comparison, оставшиеся chart overlays и comparison exports; JVM/OpenShift packs и OpenSearch overlay/opt-in correlation. Сначала сверить каждую функцию с текущей реализацией и обязательствами MVP, исключить повторную реализацию.
- [x] 4. Подготовить интеграции и выдачу отчётов: Jenkins trigger/queue/build/artifact workflow, Grafana links/render, оставшийся Confluence-ready output и publishing skeleton, skill audit/patch нагрузочных тестов. Проверить локальными контрактными сценариями, включая неизвестный результат POST, отсутствующий/повреждённый artifact и отказ транспорта. Реальные внешние действия оставить отдельной приёмке. Jenkins ранее отложен: это предложение вернуть его в подготовку полного MVP, не утверждение, что он уже реализован.
- [x] 5. Стабилизировать сборку: общий JVM/UI regression, компонентные browser tests, security/secret checks, performance smoke, воспроизводимый запуск и настройка. Исправлять блокирующие дефекты; сохранить исходные RunBundles и артефакты, не запускать clean. Подготовить CI; внешние непроведённые проверки явно оставить открытыми.
- [x] 6. Собрать пакет приёмки: инструкции запуска/ключей, примеры конфигураций без секретов, fixtures и ожидаемые результаты, список известных ограничений и короткий checklist сквозного пути/отказов. Зафиксировать проверенную сборку и отчёт готовности без объявления MVP принятым.

Параллельность: после сверки backlog независимые ветви AI, аналитика/UI, интеграции. Изменения shared файлов интегрировать последовательно; root выполняет общую проверку. Подготовку сценариев и документации вести по ходу реализации.

Граница: сквозной пользовательский прогон, новая массовая AI/статистическая оценка и внешняя приёмка выполняются отдельно. Commit/push/merge не включены в этот план. Готовность к приёмке означает: функции реализованы, локальные проверки проходят, пакет приёмки воспроизводим, оставшиеся внешние gates перечислены явно.

## Результат подготовки 2026-09-22

Выполнено в границе локальной подготовки: [отчёт](../../../mvp-readiness-2026-09-22.md),
[чеклист отдельной приёмки](../../../mvp-acceptance-checklist.md).
381 JVM tests (0 failures/errors, 9 skipped), 47 browser scenarios, Python9,
Node relay, sanitized WindowsPowerShell5/Docker fake preflight и installDist прошли.

Сокращения поставки зафиксированы явно: onboarding — manifest-only, без автоматической
AI-адаптации произвольного кода; Confluence — локальный XHTML и publishing skeleton,
без настроенной Cloud/DC strategy; static chart — SVG, без PNG renderer.
Форматированные analytics exports содержат N-run table, transactions — UI/JSON.
Наличие этих ограниченных функций не означает принятие полного продукта.
Новые внешние requests, реальные jobs, публикация, commit/push/merge не выполнялись.
