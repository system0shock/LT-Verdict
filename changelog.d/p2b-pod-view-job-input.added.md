- Подача `pod-view.v1` в анализ (платформа, срез P2b; ADR 0020): флаг
  `--pod-view` команды `ltv analyze` и необязательная часть `pod_view` запроса
  `POST /api/jobs` (до 12 MiB; предел частей запроса поднят с 24 до 25). Файл
  принимается только вместе с файлом ресурсов и не сочетается с онлайн-сбором
  (`source_request`). До записи анализа проверяется привязка: `POD_VIEW_RESOURCE_REQUIRED`,
  `POD_VIEW_INPUT_MISMATCH`, `POD_VIEW_SNAPSHOT_MISMATCH`, `POD_VIEW_ARM_MISMATCH`,
  `POD_VIEW_GRID_MISMATCH`; в API это `422 INVALID_POD_VIEW`, в CLI - код 4.
  Канонический файл сохраняется как `pod-view.json` в каталоге анализа и в
  манифесте. Чтение сохранённого файла сверяет его SHA-256 с манифестом и
  identity, поэтому подмена байт при том же размере обнаруживается. Условное
  изменение identity: только у анализов с pod-view в identity появляются поля
  `pod_view_sha256` и `pod_view_version` (такой анализ получает свой
  `analysis_id`). Без pod-view байты identity и результата прежние, результат,
  вердикт и ключ сопоставимости не меняются ни там, ни там. Чтение pod-view через
  API, экраны и производитель файла пока не подключены (срезы P2c-P2e, P4).
