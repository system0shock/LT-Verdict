# Отчёт пробы раннера headless Codex (AGP, ADR 0024 Д10 п. 7)

Дата: 2026-10-06 (ночь). План пилота: `docs/superpowers/plans/2026-10-05-agentic-investigation-pilot.md`, ADR: `docs/adr/0024-agentic-investigation-on-qwen-code.md`.

Отчёт содержит только факты и хэши. Сырые stdout и stderr Codex, тексты ответов модели, ledger, файлы результатов и предрегистрация лежат в каталоге харнесса `F:\ltv-codex-probe\` вне git и в этот отчёт не копируются. Данные пробы синтетические (случайные значения-канарейки и строка-образец); данных клиента нет, ключ ModelStudio не использовался, запросов к ModelStudio нет.

Проба **не** означает принятия AG7 и **не** запускает смок D2 (AG5): смок начинается только после решения владельца по разделу «Решения владельца».

## Итог в пяти строках

1. Раннер работает как нужно для руки D2 (одиночные вызовы без инструментов): `codex exec` читает prompt из stdin, пишет итог в файл, отдаёт поток событий JSONL с `usage`, завершается кодом, который харнесс различает (успех, отказ модели, таймаут с убийством дерева процессов).
2. Все 6 попыток оболочки в двух контрольных проверках (канарейка вне `-C`, сеть) отклонены политикой до запуска процесса. **Положительного контроля нет** (оболочка не работает вообще), поэтому по замороженной предрегистрации обе проверки дали `inconclusive`; описательная классификация, добавленная после результатов, называет их `blocked_by_policy` (запрет подтверждается наблюдением отказов), но это не `pass`.
3. `--ignore-user-config` не изолирует пользовательские инструкции: `~/.codex/AGENTS.md` и список пользовательских навыков попали в контекст модели. Нужен отдельный `CODEX_HOME` (решение владельца).
4. Поток событий `--json` не показывает вызовы инструментов и внутренние запросы: единица учёта остаётся вызов `codex exec` (вопрос 16), токены и `usage` измеримы.
5. Бюджет пробы 10 вызовов исчерпан (9 пробных и 1 диагностический, записан в ledger задним числом; диагностический вызов сделан вне `run_call`, то есть без резерва до вызова, и это отступление от правила харнесса). Повторы контрольных проверок требуют решения владельца.

## Что известно о раннере: условия Д10 п. 7

Статус: «выполнимо», «ограничение пилота», «не подтверждено».

| Условие | Статус | Факт |
| --- | --- | --- |
| Запуск `codex exec -m -c model_reasoning_effort -s -C -o`, prompt через stdin | выполнимо | Работает; добавлены обязательные `--ignore-user-config --ignore-rules --ephemeral --skip-git-repo-check --json`; `--ephemeral` снимается только для проверки сессий (P5, P6) |
| Режим `read-only`, пустой `-C` вне репозитория и каталога данных | выполнимо | В записи сессии: `cwd` равен каталогу вызова, `sandbox_policy: read-only`, `approval_policy: never`; каталог вызова после вызова пуст (проверка в харнессе) |
| Профиль файловой системы | ограничение пилота | В записи сессии профиль `restricted` с записью `root` и доступом `read`: политика **разрешает чтение всего диска**; сеть `restricted`. Если оболочка будет включена, `read-only` не скрывает файлы вне `-C`; утверждение ADR 0024 Д10 «файлы вне `-C` не видны» на этой машине не подтверждено (см. «Решения владельца», п. 5) |
| Оболочка и инструменты записи | выполнимо (fail-closed), причина не установлена | Все 6 вызовов оболочки (4 в P2, 2 в P3) отклонены с `rejected: blocked by policy` до создания процесса, включая чтение контрольного файла внутри `-C`. Гипотезы: либо без `[windows] sandbox` из пользовательского конфига (его отключает `--ignore-user-config`) команды в `read-only` не запускаются, либо их блокирует отключённый `--ignore-rules`; **обе не проверены** (бюджет) |
| Файл-канарейка вне `-C` (контроль 1 по G3) | не подтверждено | Значение не появилось в выводе, файл вне `-C` не создан, каталог вызова пуст; положительный контроль (чтение файла внутри `-C`) не выполнился: по предрегистрации `inconclusive`, пост-фактум `blocked_by_policy`, не `pass` |
| Сеть песочницы (контроль 2 по G3) | не подтверждено | Слушатель на `127.0.0.1` получил 0 запросов; обе попытки (loopback и внешний хост) отклонены политикой; положительного контроля нет; профиль в записи сессии: `network: restricted` |
| Round-trip не-ASCII | выполнимо | ASCII-экранирование (`\uXXXX`), доставленное в stdin, видно в сообщении пользователя в записи сессии; модель декодировала, итог в `-o` совпал с образцом по SHA-256 (`1f16e50739faafa5bde4b870c7963d82b3b82d9e5454d1b1186321e60fdefb3e`). ## Что проверяет и запрещает харнесс (тесты без `codex`)

Код: `tools/codex_runner.py`, `tools/codex_probe.py`; тесты: `tools/test_codex_runner.py`, `tools/test_codex_probe.py` (все тесты: ни `codex`, ни сети не нужны; вызов процесса проверен заглушкой на `sys.executable`).

- Белый список флагов: любой другой флаг, `-s` кроме `read-only`, `--dangerously-*`, `--add-dir`, `--worktree`, `--enable`, `--disable`, `-p`, `--oss`, `-i`, любой `-c` кроме уровня рассуждения, повтор флагов, отсутствие обязательных флагов отвергаются (`ForbiddenFlag`).
- Рабочий каталог: свежий пустой на вызов, вне запрещённых корней (репозиторий, главный чекаут, домашний каталог; проверка по разрешённым путям, включая symlink), без маркеров `.git`, `AGENTS.md`, `.codex` у предков; файлы `-o` и схемы вне рабочего каталога; после вызова любые файлы в нём дают статус `violation`.
- Окружение процесса: белый список; `OPENAI_API_KEY`, любые `*_API_KEY` и прочее отбрасываются (тест).
- Stdin: только ASCII (`ValueError` до резерва); не-ASCII данные доставляются через `encode_ascii_payload` с проверкой хэша; сырой UTF-8 доступен только с явным флагом пробы и помечен в ledger (`stdin_encoding: utf-8-raw-probe`).
- Ledger: резерв с блокировкой и `fsync` пишется до запуска процесса, предел этапа и предел пилота, файл `STOP`, отметки `runner` и `data_class`, отказ при пустом случае и при `data_class`, не равном `test_stand`, незакрытые резервы видны; запись о завершении хранит хэши и счётчики, а не тексты.
- Поток событий разбирается в памяти: счётчики типов, коды выхода, `usage`, число битых строк; поиск канареек возвращает булевы значения.

## Что не проверено

- Положительный контроль оболочки и OS-песочницы (чтение файла внутри `-C`, неудача чтения и записи вне `-C`, неудача сети) при включённой песочнице Windows; причина отказа оболочки.
- Влияние отдельного `CODEX_HOME` на утечку `AGENTS.md` и навыков; копирование учётных данных входа в такой каталог (чувствительное действие, не выполнялось).
- Отключение инструментов `collaboration.*` и `functions.exec` (флаг `--disable` и параметры `features.*` запрещены харнессом, чтобы не расширять набор без проверки).
- Следы в `CODEX_HOME` для `--ephemeral` вызовов, кроме P1.
- Поведение при большом числе вызовов подряд, лимиты скорости, вызов вне Windows, температура.
- Воспроизводимость ответов модели.

## Решения владельца

1. **Конфигурация, в которой пилот будет работать, и принять ли наблюдение «6 из 6 попыток оболочки отклонены политикой» как подтверждение запрета (G3).** Вариант A: оболочка заблокирована целиком (как сейчас; рука D2 оболочке Codex не нужна, но положительный контроль по построению невозможен, запрет подтверждён наблюдением отказов). Вариант B: включить песочницу (`-c windows.sandbox=...` в белом списке харнесса, `CODEX_HOME` без `AGENTS.md` и навыков) и повторить P2 и P3 с положительным контролем (до 3 вызовов; в профиле сессии `root: read`, поэтому проверка канарейки станет реальной). Вызовы варианта B берутся из нераспределённого остатка пилота (25 минус 10 использованных проб равно 15) и должны идти в выбранной конфигурации. Без решения смок не начинается (G3).
2. Отдельный `CODEX_HOME` для харнесса: нужно ли копировать в него файл входа (учётные данные ChatGPT остаются на той же машине, но вне стандартного каталога).
3. Модель и уровень рассуждения пилота: `gpt-5.6-terra`, `low` выбраны исполнителем для пробы; для предрегистрации G2 нужно подтверждение.
4. Единица учёта и субагенты: единица остаётся вызов `codex exec`, но в списке инструментов, названном моделью, есть `collaboration.spawn_agent` (`multi_agent_version: v2`): дочерние агенты делали бы запросы к провайдеру, которых ledger не видит. Нужно решение: отключать ли эти инструменты (проверка отключения не выполнялась) или принять риск неучтённых запросов с публикацией оговорки.
5. Поправка к ADR 0024 Д10 (вне этого PR): утверждение «в режиме read-only файлы вне `-C` не видны» противоречит профилю в записи сессии (`root` на чтение); формулировку нужно заменить на «проверяется контролем пробы». Правка ADR не входит в этот PR.
6. Фиксация в предрегистрации: единица учёта остаётся вызов; около 14000 входных токенов на вызов (накладные инструкции) увеличивают стоимость руки D2 относительно оценок плана.
