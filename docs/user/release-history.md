# История релизов

Вкладка **История** (новая оболочка, `?shell=new`) показывает релизы протокола и
позволяет сохранить открытый анализ как релиз. Решение описано в
[ADR 0019](../adr/0019-release-history-and-baseline-eligibility.md). Прежний
интерфейс вкладки не получает.

## Понятия

- **Протокол** (серия, `series`) - название сценария и стенда, например «Checkout /
  test environment». Релизы одной серии сравниваются между собой.
- **Релиз** - приватная запись `local-release.v1` в каталоге данных: серия, метка
  (`label`, например версия приложения), прогон, время начала теста, анализы
  релиза (до 8, по одному на плечо стенда; пока плеч нет, один), необязательный
  профиль условий теста и заметка. Метрик в записи нет: числа берутся из
  сохранённых анализов.
- **Профиль** - шесть полей (сценарии, стенд и набор данных, модель нагрузки, цели
  и ступени, паузы, ограничения генератора). Пустые поля остаются пустыми; если
  пусты все шесть, профиль не заявлен.

## Как сохранить релиз

1. Откройте анализ (список слева или вкладка «Новый анализ»).
2. На вкладке «История» в форме «Сохранить как релиз» укажите серию (подсказка
   предлагает уже существующие) и метку; профиль и заметка необязательны.
3. Нажмите «Сохранить как релиз». Релиз появится в таблице протокола, фокус
   переходит на его строку.

Профиль предыдущего релиза серии подставляется в поля формы, над ними написано
«Подставлен профиль релиза «…»; проверьте его». Он не переносится молча: пока
хотя бы одно поле профиля непусто, кнопка недоступна без отметки «Условия теста
соответствуют заявленному профилю». Правка поля убирает надпись о подстановке,
но отметка остаётся обязательной; пустой профиль (все поля стёрты) сохраняется
как «профиль не заявлен» без отметки.

Один анализ входит ровно в один релиз: повторное сохранение даёт отказ «Этот
анализ уже входит в релиз». Серия, метка и поля профиля до 128 байт UTF-8,
заметка до 1024 байт; в записи не больше 1 000 релизов. Заметка остаётся только
в локальном хранилище: она не попадает в экспорты, ИИ-разбор и журналы. Метка и
краткое представление профиля попадают в экспорты динамики.

## Таблица релизов

Над таблицей выведен график p95 отклика по показанным релизам в порядке времени
теста. Вердикт дан формой точки и текстом, а не только цветом: круг - PASS,
квадрат - FAIL, треугольник - остальные вердикты; те же числа есть в таблице, у
каждой точки есть подпись для читалки. Релиз без числа на график не наносится и
перечислен под ним.

Таблица показывает последние четыре релиза выбранного протокола, новые сверху;
кнопка «Показать все релизы» раскрывает остальные. В строке: метка и короткий
идентификатор релиза, время начала теста (UTC), вердикты анализов, профиль, числа
p95, доли ошибок и пропускной способности. Числа берутся из сохранённой аналитики
(динамика), а не из записи релиза, поэтому их может не быть:

- «Нет чисел: превышен предел сканирования истории» - просмотр истории остановлен
  по пределу (1 000 анализов, 16 MiB метаданных, см. «Сохранённая аналитика»);
- «Нет чисел: анализ создан по другим правилам» - у анализа другой ключ
  сопоставимости, чем у самого нового релиза;
- «Нет чисел: анализ не найден» - анализ релиза удалён или повреждён.

Отсутствующее число никогда не показывается нулём. Сбой запроса динамики даёт
свою причину («не удалось получить динамику»), повреждённый анализ тоже. Если часть записей релизов
повреждена, над таблицей написано, сколько их; читаемые релизы остаются.

## Действия строки

- **Открыть** - делает анализ релиза выбранным и открывает «Обзор».
- **Сделать baseline** - назначает анализ релиза ручным baseline его серии.
  Кнопка недоступна, если анализ не может быть baseline: причина написана рядом
  («Вердикт не PASS», «Анализ неполный», «Прогон разобран не полностью», «Анализ
  не найден»); окончательное решение принимает сервер. У релиза, чей анализ сейчас
  baseline своей серии, стоит пометка «baseline».
- **Сравнить** - открывает вкладку «Сравнение» с анализом релиза; в поле «Серия
  сравнения» подставлена серия релиза, а панель показывает baseline этой серии.

- **Перепривязать анализ** - путь после смены правил анализа: заново
  проанализируйте вход (получится новый анализ того же прогона), затем в строке
  релиза выберите «Перепривязать анализ», отметьте анализ из списка анализов
  этого прогона и подтвердите. Релиз остаётся тем же (серия, время теста, метка,
  профиль и заметка не меняются), меняется только ссылка на анализ. Baseline
  серии при этом не перезакрепляется: сделайте это отдельно кнопкой «Сделать
  baseline». Анализ, уже входящий в другой релиз, сервер отвергает. Для релиза с
  несколькими плечами действие недоступно (причина написана рядом).

Если релиз содержит несколько анализов (плечи), у каждого свой набор кнопок, в
названиях кнопок для читалки указаны метка релиза и плечо.

## Профиль, предложения и статистический baseline

- Знак «другой профиль (относительно релиза «…»)» стоит у релиза, чей заявленный
  профиль отличается от профиля самого нового релиза таблицы. У релиза без
  профиля стоит «не заявлен» и знака нет: два незаявленных профиля не считаются
  совпавшими.
- «Предлагаемый baseline» отмечает предыдущий релиз той же серии и плеча с
  совпавшим заявленным профилем и пригодным анализом. Предложение не выбирается
  автоматически; без заявленного профиля у самого нового релиза вместо него
  написано «Заявите профиль релиза, чтобы получить предложение baseline».
- Статистический baseline требует не менее трёх релизов PASS одного заявленного
  профиля из разных прогонов (считаются последние 20 релизов серии, а не только четыре в таблице). Пока их меньше,
  написано, сколько найдено; на 3-4 прогонах оценка слабая (ADR 0017). Когда их
  достаточно, кнопка «Статистический baseline» открывает вкладку «Сравнение»:
  кандидатов выбирают там.

## Ограничения

- Релиз нельзя изменить или удалить из интерфейса; записи лежат в
  `<data>/releases/`.
- Ничего из этой вкладки не отправляется провайдерам ИИ.
