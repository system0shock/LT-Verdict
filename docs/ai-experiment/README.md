# Данные ИИ-экспериментов (ADR 0021): состав и пересчёт цифр

Каталог `docs/ui-mockup/ai-experiment-2026-09-30/` хранит данные экспериментов по
советам ИИ, на которых стоит [ADR 0021](../adr/0021-advisory-ai-prompt-v2-and-schema-retry.md):
серии v1 (прямой API), v2 и v3 (headless Qwen Code через relay) и холдаут 38 случаев.
Путь не менялся: на него ссылаются ADR 0021, ADR 0024 и планы. Данные добавлены решением
владельца 2026-10-08 (перечень работ, W1.4) и заменяют решение 2026-10-04 «эксперимент не
коммитим» (ADR 0021, вопрос 10); строки ADR «вне git» после слияния устарели.

Файлы лежат в том виде, в каком их выдал эксперимент. Байты не правились: на предрегистрациях
лежат SHA-256, и правило `-text` в `.gitattributes` запрещает git менять концы строк.

## Пересчёт

```text
python docs/ai-experiment/recompute_adr0021.py
```

Нужен Python 3 и ничего больше. Скрипт ничего не пишет и печатает по строке на проверку
(`OK` или `FAIL`, ожидаемое и полученное). Код выхода: 0 все проверки совпали, 1 цифра
расходится, 2 входной файл отсутствует или повреждён. Занимает около трёх секунд. Данные другого
каталога: `--data-dir`.

Скрипт сверяет цифры двумя путями:

- сам, из рецензий, ключей слепой разметки, журнала запросов и сохранённых результатов оракула
  (`INT-*`, `LED-*`, `V1-1`..`V1-8`, `V2-1`..`V2-6`, `V2-11`, `HO-*`);
- через замороженный срез анализа харнесса `harness-264a340/aiexp/` (строки таблицы ADR,
  которые держатся на оракуле: `V1-9`, `V2-7`..`V2-10`, `V2-12`).

## Пины харнесса и то, что не пересчитывается

Ветки харнесса существуют только в чекауте автора (на `origin` их нет), поэтому пины по SHA
служат справкой; для пересчёта ADR 0021 хватает среза в репозитории.

| Коммит | Ветка | Для чего |
| --- | --- | --- |
| `264a340` | `test/ai-experiment-harness` | v1 и v2: срез анализа в `harness-264a340/aiexp/` (модули побайтно из коммита, без правок) |
| `bc1d6e4` | `test/ai-holdout-h1-h2` | холдаут: `holdout_eval.py`, `run_holdout.py`, оракул v2 |
| `7928e3f` | `test/ai-pilot-exec` | пилот ADR 0024 (не нужен для ADR 0021) |

Не пересчитывается этим репозиторием:

- Критерии P3 (формат и повтор), P4 (целостность, canary) и решение холдаута по правилу ADR D7
  (`holdout/eval/summary.json`, `holdout/eval/oracle.json`): для них нужен `holdout_eval.py`
  и оракул v2 из `bc1d6e4`. Версия `holdout_eval.py` в ветке отличается от той, чей хэш записан в
  `holdout/eval/DEFINITIONS_COMMITTED.txt`, и самого файла в репозитории нет.
- Оракул в голове ветки харнесса (после `abcd0f6`, область отрицания) даёт на данных v2 другие
  цифры (кейсов 7 / 3 / 2 вместо 7 / 7 / 5): отчёт v2 получен оракулом до этой правки. Поэтому срез
  заморожен на `264a340`.
- Цифры v3 в ADR 0021 не использованы и скриптом не проверяются (см. `v3/analysis/`).
- Сам эксперимент не повторяется: нужны ключ ModelStudio и харнесс.

## Что внутри данных и что с ним делали

- Секретов нет: сканы `gitleaks` и шаблонный поиск прошли по всему коммитимому дереву и по
  содержимому `runs_raw.tar.gz`. В отчётах упоминаются имена переменных окружения
  (`BAILIAN_TOKEN_PLAN_API_KEY`, `OPENAI_API_KEY=relay-placeholder`), значений нет.
- Строки `CNRY-<СЛОВО>-<ЧИСЛО>` в `holdout/generation/` и в кейсах холдаута вымышленные canary для проверки
  инъекций. Для них в `.gitleaks.toml` стоит точечное исключение (путь и шаблон значения).
- Три файла `holdout/generation/**/report-*.json` содержат локальный путь временного каталога сеанса
  (`C:/Users/<имя>/AppData/Local/Temp/...`), файлы `*.provenance.json` содержат пути рабочих деревьев
  автора (`F:\Coding\...`). Файлы не правились, чтобы не менять данные.
- Исключения для CI (`markdownlint`, `lychee`) относятся только к каталогу данных и разбору
  дефектов: там лежат отчёты в том виде, как их сохранил оркестратор.
