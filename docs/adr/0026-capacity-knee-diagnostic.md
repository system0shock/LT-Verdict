# ADR 0026: Диагностический детектор колена ёмкости

Дата: 2026-10-07 (принято и откалибровано в W3.4: 2026-11-25).

Статус: Accepted.

## Контекст

ADR 0009 осознанно исключил детектор колена: это новый статистический метод
без утверждённой калибровки, поэтому ядро отдаёт `capacity_knee: null` и
`knee_reason: KNEE_DETECTOR_NOT_IMPLEMENTED`. Дорожная карта методов
(`docs/statistical-method-roadmap.md`) предусматривает «кусочную load-response
regression» при условии, что диагностическое колено не заменяет подтверждённую
ёмкость по SLA. План v0.6 (`docs/development-plan-v0.6.md`) повторяет: колено
остаётся диагностикой. Владелец хочет показать на демо 2026-10-08 «определение
точки деградации» для теста максимума.

Жёсткие границы решения:

1. Подтверждённая граница ёмкости (`lower_inclusive`, `upper_exclusive`),
   вердикты ступеней и вердикт ёмкости не меняются и не зависят от колена.
2. Колено помечено `diagnostic_only: true` и `calibrated: true` с откалиброванным
   уровнем достоверности (`HIGH` / `MEDIUM` / `NONE`).
3. Советник ИИ видит `capacity_summary.capacity_knee` и `knee_reason` при
   обновлении `system-prompt-v2.md` (`eb02f2a6653697509b356fffddade39e02184e3d9f8eb28101293d1a483b294b`);
   `capacity_knee_diagnostic` остаётся отдельным элементом `evidence`.

## Решение

### Метод `piecewise-hinge-ln-p95.v2`

Входы: по каждой ступени плана достигнутая нагрузка `x_i` (`achieved`, p05 за
10 с, то же значение, что в границе ёмкости) и p95 времени отклика `y_i` в окне
ступени (`overall`, миллисекунды, из метрик окна; политика для этого не нужна).
Ступени идут в порядке плана.

Модель на логарифме отклика: `ln(y) = a + b*x + c*max(0, x - x_k)`, то есть
ломаная с изломом в `x_k`, равным нагрузке одной из ступеней. Для каждого
кандидата `k` от третьей ступени до предпоследней модель подгоняется методом
наименьших квадратов (нормальные уравнения 3 на 3, арифметика `double`,
`StrictMath.log`/`exp`, без случайных чисел), выбирается `k` с минимальной
суммой квадратов остатков (SSE). При равенстве SSE на разных нагрузках побеждает
меньшая нагрузка; при совпадении нагрузки на ступенях плато равный минимум SSE
продвигается к концу плато (`x_k == x_{best}`).
Допускаются плато достигнутой нагрузки (`left.load <= right.load`, отказ
`KNEE_LOAD_NOT_INCREASING` только при снижении нагрузки или полностью равной
нагрузке по всему прогону): при малой дисперсии нагрузки устойчивой ветки
(`variance <= 1e-4`) либо отрицательном OLS-наклоне (`slope < 0.0`) наклон
устойчивой ветки полагается `0.0` (исключая экстраполяцию шума через малый
интервал нагрузки и переполнение `exp`), а при плато за кандидатом
(`x_{k+1} == x_k`, включая середину и верхний край прогона) вместо `max(0, x - x_k)`
подгоняется ступенчато-линейный базис `1_{i > k} * (1 + x - x_k)` (или только
с этим слагаемым при `x_k <= x_0`), исключающий вырождение матрицы нормальных
уравнений (`NaN`). Если SSE одной прямой `<= 1e-12` (например, ровно два
различных уровня нагрузки), возвращается `KNEE_NO_BREAK`.
Логарифм нужен, чтобы скачок на порядки (52 мс, затем 11,5 с) не заглушал
остальные ступени в SSE: без него при ступенчатом нарастании излом уходит на
ступень позже.

Колено — интервал `[x_k, x_{k+1})`: от последней ступени устойчивой ветки до
первой ступени за изломом. Метод не интерполирует точку внутри интервала: если
за изломом одна ступень, положение излома внутри интервала данными не
определяется. Поэтому в `capacity_knee_diagnostic` названы обе ступени, в
`capacity_summary.capacity_knee` записывается `last_stable_load` (либо `null` при
отказе, с `knee_reason = "KNEE_DETECTED"` или кодом отказа `KNEE_*`), а в
интерфейсе колено показывается интервалом и маркером на графике p95.

### Отказ вместо догадки

Результат `DETECTED` выдаётся только если выполнены все условия; иначе
`NOT_DETECTED` с одним кодом причины (проверяются в этом порядке):

| Код | Условие отказа |
| --- | --- |
| `KNEE_RUN_NOT_VALID` | прогон не `VALID` |
| `KNEE_STAGE_DATA_MISSING` | у ступени нет `achieved`, нет запросов в окне либо есть `CAPACITY_INSUFFICIENT_SAMPLES` |
| `KNEE_TOO_FEW_STAGES` | ступеней меньше пяти |
| `KNEE_LOAD_NOT_INCREASING` | достигнутая нагрузка снижается на более высокой ступени либо постоянна на всём прогоне |
| `KNEE_NO_BREAK` | SSE ломаной больше 25% SSE одной прямой (излом не улучшает описание) либо прямая точная |
| `KNEE_BREAK_NOT_MATERIAL` | p95 за изломом выше экстраполяции устойчивой ветки меньше чем в 1,5 раза |
| `KNEE_BREAK_WITHIN_NOISE` | превышение над экстраполяцией меньше трёх стандартных отклонений остатков устойчивой ветки |

### Калибровка и измеренная точность (W3.4)

Калибровка выполнена на детерминированном корпусе из 430 кривых (130 кривых с
истинным изломом и 300 нулевых кривых):

- 80 параметрических кривых с изломом и нарастанием деградации (5–10 ступеней, `cv = 0,01..0,07`, seed `20261125L`);
- 30 параметрических кривых с плато нагрузки (верхнее и доизломное плато, `cv = 0,01..0,05`, seed `20261125L`);
- 20 параметрических кривых с разрывом на внутренней ступени плато (`x_{k+1} == x_k < x_{last}`, `cv = 0,01..0,05`, seed `20261125L`);
- 100 основных нулевых кривых (плоские, линейный дрейф, слабый экспоненциальный рост, плато без скачка, `cv = 0,02..0,10`, seed `20261125L`);
- 200 независимых контрольных нулевых кривых (плоские, линейный дрейф, слабый рост, плато без скачка и префикс с малой дисперсией нагрузки, `cv = 0,03..0,12`, seed `20261126L`).

Измеренные метрики при порогах `max_sse_ratio = 0.25`, `min_excess_factor = 1.5`, `noise_multiplier = 3`:

- полнота обнаружения истинного колена (recall): **96,2% (125/130)**;
- точное попадание в ступень излома: **96,2% (125/130)**;
- точность в пределах ±1 ступени: **96,2% (125/130)**;
- ложные срабатывания (FPR) на основном нулевом наборе: **0,0% (0/100)**, на контрольном наборе: **0,0% (0/200)**.
- Воспроизводимая проверка закреплена в `CapacityKneeCalibrationTest`.

Уровень достоверности (`confidence`):

- `HIGH`: `sse_ratio <= 0,05` и `excess_factor >= 3,0`;
- `MEDIUM`: `DETECTED`, если хотя бы один из показателей мягче порога `HIGH`;
- `NONE`: при `NOT_DETECTED`.

Используется только p95 времени отклика. Доля ошибок не используется: второй
ряд требует отдельных правил совмещения двух кривых.

### Где результат хранится

Элемент `evidence` в `analysis-result.v1`:
`{"type": "capacity_knee_diagnostic", "id": "capacity-knee-diagnostic", ...}`,
добавляется после `capacity-summary` только в режиме `capacity_step`, когда
ядро знает метрики окон ступеней. Поля: `method` (`piecewise-hinge-ln-p95.v2`),
`metric`, `load_axis`, `unit`, `status` (`DETECTED` или `NOT_DETECTED`),
`confidence` (`HIGH`, `MEDIUM`, `NONE`), `calibrated: true`,
`diagnostic_only: true`, `last_stable_stage_id`/`last_stable_load`,
`first_degraded_stage_id`/`first_degraded_load` (или `null`), `sse_ratio`,
`excess_factor`, `reasons`, `points` (ступень, нагрузка, p95), `parameters`.
Схема: `docs/contracts/capacity/v1/capacity-knee-diagnostic.schema.json`.

В `capacity_summary` и `capacity.json` поля `capacity_knee` и `knee_reason`
заполняются из откалиброванного детектора: при `DETECTED` — строковое значение
`last_stable_load` и `knee_reason = "KNEE_DETECTED"`, при отказе — `null` и
код отказа `KNEE_*` (`KNEE_STAGE_DATA_MISSING`, если метрики окон не переданы).

### Советник ИИ

`AdvisoryEvidenceBuilder` по-прежнему пропускает `capacity_knee_diagnostic`,
сохраняя индексы остальных элементов `evidence`. `capacity_summary` передаётся в
доказательства ИИ вместе с откалиброванным `capacity_knee` и `knee_reason`, а
`docs/contracts/advice/v1/system-prompt-v2.md` обновлён под откалиброванное
колено (SHA-256 `eb02f2a6653697509b356fffddade39e02184e3d9f8eb28101293d1a483b294b`).

### Identity и сопоставимость

Версия метода в `identity.json` (`capacity_knee_method`) обновлена до
`"piecewise-hinge-ln-p95.v2"` (только при плане ёмкости). Повторный анализ
тех же входов получает новый `analysis_id`, а ранее сохранённые анализы
остаются неизменными; ключ сопоставимости baseline и сравнения прогонов не
меняется. Анализы без плана ёмкости (`standard` и `load-stages.v1`) не
меняются побайтно.

### Интерфейс

В таблице «Ёмкость» и в блоке ёмкости «Обзора» новой оболочки показываются
строка «Точка перегиба» (из `capacity_summary.capacity_knee` / `knee_reason`),
строка «Колено (диагностика)» с пометкой «откалибровано, не влияет на границу
ёмкости и вердикт», а также интерактивный SVG-график ECharts зависимости p95 (и
опционально p99) от достигнутой нагрузки с границами ёмкости, интервалом колена
и явным отображением проверок генератора нагрузки (`CAPACITY_GUARD_FAILED` /
`CAPACITY_GUARD_MISSING`). Старая оболочка не меняется.

## Отклонённые альтернативы

- Непрерывная подгонка положения узла между ступенями: при одной ступени за
  изломом узел данными не определяется, выдавать промежуточное число значило бы угадывать.
- Подгонка p95 в миллисекундах без логарифма: SSE определяется скачком на
  порядки, и при ступенчатом нарастании излом уходит на ступень позже.
- Порог «p95 выше X» или «рост в N раз»: это калибровочное правило вроде SLA,
  оно дублирует правила политики.
- Отказ на любом плато нагрузки: при насыщении генератора или ограничении пула
  достигнутая нагрузка выходит на плато при росте p95, поэтому плато должно
  обрабатываться без вырождения нормальных уравнений.
