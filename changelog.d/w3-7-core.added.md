- Ядро синтеза инцидентов v0 (W3.7, PR 1, ADR 0029): чистая функция `synthesizeIncidents(run_validity,
  findings, evidence)` собирает документ `incident.v1` (не более 7 карточек «Обзора», не более 64
  сохранённых, отрицательные свидетельства, следующие проверки, тексты только из шаблонов без причинных
  слов, статус `NOT_EVALUATED` для непригодного прогона). Функция пока никуда не подключена: ни анализ,
  ни `analysis-result.json`, ни `analysis_id`, ни identity, ни UI и отчёты не меняются, пользователь
  изменений не видит (подключение в следующих PR W3.7). В схему `analysis-result.v1` добавлено
  необязательное свойство `incidents` по ссылке на схему `incident.v1`; `tools/verify_slice0.py` проверяет
  эту ссылку и получил параметр `check_wording` (имя транзакции вроде `cause-list` не должно ломать проверку
  отрисованных текстов). Известное расхождение контракта: примеры `transaction-and-resource-in-window` и
  `overlapping-resource-incidents` показывают проверки окна на одном инциденте, а ADR относит их ко всему
  окну; ядро следует тексту ADR, расхождение записано как вопрос владельцу.
