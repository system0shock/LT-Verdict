- API baseline работает со слотами по паре `(series, arm)` (ADR 0019, раздел 7, срез
  B2): `POST /api/baseline` пишет слот (серия нормализуется: NFC и обрезка краёв,
  плечо берётся из identity анализа-эталона) и не затирает baseline другой серии;
  `GET /api/baseline` сохраняет поле `baseline` для прежнего файла и добавляет
  `baselines` (`{series, arm, source, baseline}`); `DELETE /api/baseline` принимает
  необязательные `series` и `arm` для адресного удаления (без параметров очищает
  только прежний файл; `arm` без `series` даёт `400`). Comparison,
  baseline-conditions и analytics выбирают слот по серии релиза текущего анализа и
  плечу его identity; для анализа вне релиза серия задаётся параметром `series`,
  без него читается только прежний `baseline.json`. Новые ответы `422`:
  `BASELINE_SERIES_CONFLICT` (`series` противоречит серии релиза),
  `BASELINE_SLOTS_LIMIT_REACHED` (64 слота) и `BASELINE_CONDITIONS_LIMIT_REACHED`
  (4 096 записей условий), у двух последних предел в `error.limit`. Изменение
  аддитивно, форматы `local-baseline.v1` и записей условий не менялись.
  Известное ограничение до среза B3: панель baseline показывает один baseline
  (слот серии из поля, иначе первый) и передаёт его серию в сравнение, условия и
  очистку; список слотов в интерфейсе и `series` в панели сохранённого анализа
  (сравнение транзакций) появятся в B3, пока эталон сравнивается там только для
  анализов релиза серии.
