# ADR 0034: Допуск усечённой последней записи JMeter JTL CSV

Дата: 2026-10-13.

Статус: Accepted (волна 0, 2026-11-20). Номер 0034 свободен
в текущем worktree после 0033; перед слиянием его нужно перепроверить. ADR фиксирует
решение владельца от 2026-10-12 для C1 до реализации.

## Контекст

JMeter может остановиться во время записи последнего сэмпла. Сейчас неполная запись
делает весь CSV невалидным. Нужно сохранить завершённые записи и явно показать потерю
хвоста, не ослабляя проверку остальных повреждений и лимитов ресурсов.

## Решение

Неполная последняя запись допускается только при одновременном выполнении условий:
последний байт файла не `\n`, а последняя CSV-запись содержит меньше столбцов, чем
заголовок, либо заканчивается внутри открытого quoted field. Запись может содержать
переводы строк внутри кавычек; отбрасывается вся незавершённая запись, а не только её
последняя физическая строка. Полная валидная запись без завершающего перевода строки
принимается без предупреждения. Поддерживаются LF и CRLF. Полная запись с оставшимся CR
при отсутствии только LF проверяется по прежним правилам CSV и не получает отдельного допуска.

Лишние столбцы, неверные числа или boolean в полной записи, недопустимые кавычки,
повреждённый UTF-8, повреждение в середине и неполная последняя запись с завершающим
`\n` остаются фатальными (`MALFORMED_JMETER_CSV`). Действующие отдельные коды ошибок
заголовка, timestamp и `RESOURCE_LIMIT_EXCEEDED` сохраняются. Если после заголовка нет
ни одной полной записи, результат `EMPTY_INPUT`, а не успешный анализ пустой выборки.
Перед отбрасыванием проверяются также присутствующие завершённые обязательные поля:
недостающие столбцы не скрывают неверный timestamp, elapsed или boolean в полях,
после которых есть разделитель. Последнее присутствующее поле не валидируется как
завершённое значение независимо от кавычек; лимиты размера сохраняются и для него.

Успешный `ParseReport` остаётся `RunValidity.VALID`. Его существующий список
`diagnostics` содержит одно предупреждение `JMETER_CSV_TRUNCATED_TAIL` с байтовым
`sourceOffset` начала отброшенной записи и точным счётчиком `discarded_bytes=N` в
`message`. N — число исходных UTF-8 байтов всей отброшенной записи, включая переводы
строк внутри quoted field и оставшийся CR. Это стабильный формат счётчика; отдельное
поле схемы не добавляется. `processedBytes` учитывает весь прочитанный файл.

Предупреждение передаётся существующим путём в `analysis-result.v1`: finding и evidence
типа `diagnostic`, с `code`, `message`, `source_offset`. Оно не ограничивает покрытие
анализа и не блокирует policy verdict: метрики и правила считают только полные записи.
HTML показывает предупреждение и счётчик в основной части отчёта; AsciiDoc выводит
их отдельным блоком из того же diagnostic evidence. Без предупреждения новые блоки
отсутствуют, прежние golden-результаты и отчёты побайтово не меняются.

`previewMixedParents` использует тот же критерий последней записи: отброшенный хвост
не считается ни parent, ни sampler. Предупреждение создаёт только основной проход;
повторный основной проход AnalysisService возвращает ту же диагностику и счётчик.

### Identity и совместимость

Версии модулей identity, канонический JSON identity, его хэши и алгоритмы вычисления
`run_id`/`analysis_id` не меняются. Исходный усечённый файл уже имеет собственный source
sha256; раньше такой вход отвергался и не создавал успешного артефакта. Предупреждение
входит только в результат, не в хэшируемый JSON identity. `analysis-result` для усечённого
входа содержит новую диагностику; формат и канонизация результата не меняются.
Старые артефакты читаются как прежде; старые успешные входы не получают предупреждения.
AnalysisService сохраняет также `INVALID` и возвращает кэш до разбора. Поэтому ранее
сохранённый `INVALID` для тех же исходных байтов и параметров остаётся прежним: этот ADR
не вводит миграцию или автоматический пересчёт исторических артефактов. Новый допуск
работает при отсутствии готового анализа с тем же identity (например, в новом каталоге
данных). Это сознательное ограничение решения без изменения identity; обновление
старого результата под тем же id нарушило бы неизменяемость сохранённых артефактов.
Новых production-зависимостей нет.

## Публичные контракты, которые меняет эта работа

| Контракт | Изменение | Совместимость |
| --- | --- | --- |
| Ingest JMeter CSV | Допуск только определённого выше хвоста | Расширение принимаемых входов |
| `analysis-result.v1` | Новый diagnostic code и `discarded_bytes=N` в message | Существующие поля и версия схемы |
| HTML/AsciiDoc | Видимое предупреждение о потерянных байтах | Без изменений для полных входов |

## Что не входит

- Допуск других повреждений, пороги потери данных, восстановление повреждённой записи.
- Изменения XML/Gatling, identity, схем JSON и зависимостей.

## Отклонённые альтернативы

- Пропускать любые плохие строки: скрывает повреждения в середине и меняет выборку без
  надёжного признака остановки записи.
- Разрешать потери до порога по доле строк или байтов: размер файла не доказывает
  безопасность повреждения, а небольшой файл получает другое поведение.
- Обновить версию ingest в identity или включить счётчик в хэшируемый JSON: меняет
  identity всех полных входов без необходимости; исходные байты уже связаны source sha256.

## Следствия

Пользователь получает анализ только полных сэмплов и видит точную потерю байтов. Успешный
анализ больше не означает, что последняя запись обязательно была завершена. Тесты
неусечённых файлов и golden-фикстуры должны оставаться прежними.

## Тест-критерии

1. Неполный хвост без LF удаляется; предыдущие записи и точный UTF-8 счётчик сохраняются.
2. Полная последняя запись без LF принимается без диагностики.
3. Открытая кавычка, включая multiline field, в хвосте не вызывает исключения.
4. Повреждение с LF, в середине, лишние столбцы и неверные значения остаются фатальными.
5. Заголовок с единственным неполным хвостом даёт `EMPTY_INPUT`.
6. LF/CRLF и previewMixedParents соблюдают одно правило.
7. AnalysisService сохраняет diagnostic evidence, не блокирует PASS и передаёт счётчик
   в HTML/AsciiDoc; identity полного входа и существующие fixtures не меняются.
